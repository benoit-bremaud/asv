## Findings

Severities follow the rubric (a failed P0 item is a Must). The owner may downgrade F1 to F3 as a UI-debt
decision; proposed issue titles are for the owner to file, nothing was filed.

1. 🔴 Must — **F1** `fix(web): make the account dialog modal` (A11Y-01).
   Seen: "Mon compte" renders `<dialog open>` (non-modal): Esc does nothing, focus stays on the opener button, and the dialog stays open when you move to the rooms screen.
   Repro: enter as guest, focus "Mon compte", Enter, press Esc, click a room: the panel is still there.
   Suggested fix: open it with `showModal()` (gives Esc, focus trap, return of focus) and close it on route change.
2. 🔴 Must — **F2** `fix(web): add one h1 per screen` (A11Y-02).
   Seen: no `h1` on any screen; headings start at `h2`.
   Suggested fix: make the header brand or the screen title an `h1` (visually unchanged).
3. 🔴 Must — **F3** `fix(web): private windows must not cover the room input` (A11Y-06, USA).
   Seen: the fixed private window sits over the room's message field and "envoyer" (1440 px: "envoyer" and "smileys" hidden; 390 px: the whole field covered, only visible after minimising). `elementFromPoint` on the room button returns the window.
   Repro: two members, open a private window, look at the bottom right of the room (screenshots 09, 19).
   Suggested fix: reserve space (padding-bottom of the room screen equal to the dock height) or dock the window above the field on narrow screens.
4. 🟡 Should — **F4** `feat(log): add content id and operation to contribution lines` (security-and-rgpd §1, BR-060, ADR-0014).
   Seen: a contribution line is `{kind, connectionId, protocols, at}`; `ContributionLine` has no content id or operation although ADR-0014 states a Prime Minister's injunction is in force since 2026-10-21 and the live tester server is exposed. The hub diagram `platform/04c` records this as "not in brick 7a", so it is a deferral, not a regression: the owner should decide before the testers' traffic grows.
5. 🟡 Should — **F5** `fix(web): do not steal focus when a private message arrives` (USA / A11Y).
   Seen: when QaDeux wrote, the receiver's `document.activeElement` became the private window's input although the user was elsewhere (typing in the room). Opening the window on first message is fine; moving focus is not.
6. 🟡 Should — **F6** `fix(web): clear or expire notices` (extends #60).
   Seen: the top notice survives later successes and never times out: "Doucement ! 5 messages…" stayed for minutes, "Nom invalide…" stayed after the room was created, "Si l'adresse peut recevoir un code…" stayed after sign-in. Same family as the stale "Mauvais code." of #60; suggest one fix (clear on next successful server answer, auto-dismiss after about 8 s, keep `role="alert"`).
7. 🟡 Should — **F7** `fix(server): add Permissions-Policy` (SEC-01). Seen: no `Permissions-Policy` header (curl `-I /`). Suggest `camera=(), microphone=(), geolocation=(), payment=()` through `secureHeaders` `permissionsPolicy`, and say so in BR-086.
8. 🔵 Nice — **N1** pseudo field silently cuts at 20 characters (a 21-character paste is accepted as 20): show the counter or the rule.
9. 🔵 Nice — **N2** search panel shows "2 caractères au moins." and "aucun chatteur trouvé" together for a one-character query (13).
10. 🔵 Nice — **N3** age below 18 is stopped by the browser's native bubble in the browser's language (English here), not by the French `entryRefused.age` text; the French message is only reachable by bypassing the form.
11. 🔵 Nice — **N4** after a server restart the client returns to the entry screen with no explanation (22); a one-line notice "Session perdue, reconnecte-toi" would help. Also on a full page reload the resumed user is still counted as a member of the room (Blabla (2)) but lands on the rooms list without the room tab; the state diagram only promises history after a socket loss, so confirm intent.
12. 🔵 Nice — **N5** server `seq` is one global counter shared by all connections (first message of a new connection had seq 53): leaks overall activity volume; a per-connection counter is enough.
13. 🔵 Nice — **N6** no `<meta name="description">`, plain-text 404 (favicon is #62).
14. 🔵 Nice — **N7** footer legal buttons are 22 px high (passes WCAG 2.5.8 by spacing, below the 24 px house floor).
15. 🔵 Nice — **N8** hashed assets carry no `Cache-Control: public, max-age=31536000, immutable` and no `ETag` from the origin.
16. 🔵 Nice — **N9** name the device cookie `__Host-asv_device` in tunnel mode (already `Secure`, `Path=/`, no `Domain`).
